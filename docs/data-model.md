# Data Model

## 核心实体

| 实体 | 用途 | 关键约束 |
| --- | --- | --- |
| `stores` | 店铺边界 | 代码唯一，历史存在时不物理删除 |
| `app_users` | 用户与状态 | 邮箱唯一，密码仅保存 Argon2id 哈希 |
| `user_store_memberships` | 用户可访问店铺 | 用户与店铺联合主键 |
| `products` | SKU 主数据 | SKU 全局唯一，店铺变体组合唯一 |
| `suppliers` | 店铺供应商 | 代码店内唯一，创建后禁止迁店 |
| `inventory_balances` | 可用与待入余额 | 两类数量均不得为负 |
| `operation_batches` | 批次状态与幂等 | 店铺、类型、状态和文件关联 |
| `pending_receipts` | 到仓待实点数量 | 剩余数量不得为负 |
| `inventory_ledger` | 不可变库存流水 | 只允许插入，不允许更新或删除 |
| `uploaded_files` | Excel 原文件元数据 | 店铺、用途与 SHA-256 防重复 |
| `audit_events` | 安全与业务审计 | 追加写，保留请求和操作上下文 |

## 数量不变量

- `available_qty >= 0`
- `pending_qty >= 0`
- 到仓只增加待入，不增加可用库存。
- 实点入库增加可用库存，并减少不超过剩余值的待入库存。
- 出库确认时重新锁定并检查余额；任一 SKU 不足则整批回滚。
- 库存纠错输入目标数量，数据库计算差额并生成流水。
- 箱规为待确认时，即使存在临时数值，也不得用于正式按箱入账。

所有店铺级关系均通过 `store_id`、RLS 与复合外键共同约束，避免只依赖前端过滤。
